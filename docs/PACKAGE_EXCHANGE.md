# Обмен пакетами .pkg

Пакет переносит записи мероприятий между экземплярами системы. Реализация — в
`backend/internal/exchange` (формат, экспорт, импорт, сопоставление, сравнение,
протокол разногласий) поверх интерфейса `cryptoengine.Engine`.

Пакет не обращается к БД. Импорт возвращает проверенные записи и различия;
применять их или нет, решает оператор, и до этого данные не меняются.

## Формат

```
"CCPKG"   1 версия формата   uint32 длина + манифест   uint32 длина + подпись   uint64 длина + шифртекст
```

* **Манифест** — канонический JSON (ключи по алфавиту, без пробелов): формат,
  версия, схема, время создания, отправитель (организация, подписант,
  сертификат), получатели с обёрнутыми ключами, описание шифра (провайдер,
  алгоритм, SHA-256 содержимого и шифртекста), отчётный год, период, число
  записей. Записанные байты обязаны быть канонической формой: подпись покрывает
  именно их.
* **Подпись** покрывает манифест. Так как в манифесте зафиксирован SHA-256
  шифртекста, изменение любой части пакета ломает проверку до расшифровки.
* **Шифртекст** — gzip от `{"records":[…]}`, зашифрованный для каждого
  получателя: один ключ содержимого, обёрнутый отдельно под ключ каждого.

Пределы: файл 64 МБ, манифест 1 МБ, подпись 64 КБ, после распаковки 256 МБ,
записей 200 000, получателей 64. Заявленные длины проверяются до выделения
памяти.

## Порядок проверки при импорте

Всё, что не требует ключа получателя, проверяется до расшифровки:

1. форма файла и размеры; 2. канонический манифест, формат, версия, схема;
3. алгоритмы — только из закрытых списков политики; 4. год и период;
5. SHA-256 шифртекста; 6. подпись манифеста; 7. цепочка сертификатов подписанта
(срок, отзыв, назначение, доверенный корень); 8. организация в манифесте —
владелец сертификата; 9. пакет адресован этому получателю; и только затем —
расшифровка, распаковка с пределом, разбор JSON и сверка числа записей.

## Провайдер

`cryptoengine.Software` (X25519 + HKDF-SHA256 + AES-256-GCM, подпись Ed25519)
реализует интерфейс на стандартной библиотеке и **не является производственным
профилем**: выбор провайдера и допустимых видов подписи — решение CRYPTO-00.
КриптоПро или иной провайдер подключается через тот же интерфейс и формат не
меняет. Закрытые ключи в Engine, БД и HTTP не передаются — только ссылки.

## Составной ключ сопоставления

Записи двух экземпляров сопоставляются по ключу
**вид + специальность + ФИО + предмет + период**. Идентификаторы экземпляра
(UUID партнёра, сотрудника, наставника) не участвуют: у другого экземпляра они
другие.

| Вид | ФИО | Специальность | Предмет | Период |
|---|---|---|---|---|
| teachers | teacher_full_name | specialty_code, training_direction | course_name | семестр |
| internship, employment_practice | student_full_name | specialty_code | course | period_start..period_end |
| ood_rpd | expert_full_name | specialty_code | program_name + doc_type + activity_type | — |
| top_it | — | — | project_name, program_name | program_wave |
| it_clubs | employee_full_name | — | program_name | — |
| teacher_training | — | — | program_name | — |
| edu_content | — | — | platform_name | digital_trace_period_start..end |
| minc_decision | — | — | decision_number, decision_reference, instruction_reference | implementation_start |

Из нескольких возможных полей берётся первое непустое. Запись, у которой нет ни
ФИО, ни предмета, сопоставить нельзя — это ошибка, а не «пустой ключ».

### Нормализация

* **Названия и ФИО:** регистр не важен; «ё» = «е»; любая пунктуация и любое
  число пробелов — один пробел.
* **Коды и даты:** пробелы удаляются, регистр не важен; точки и дефисы
  сохраняются (`09.03.01`, `2026-09-01`).
* **Числа:** `3`, `3.0` и `"3"` из JSON — одно и то же значение.
* **Инициалы не раскрываются:** «Иванов И. И.» и «Иванов Иван Иванович» —
  разные ключи. Нечёткое сопоставление людей даёт ложные совпадения, а ложное
  совпадение опаснее пропущенного.

## Сравнение

Исходы: `identical`, `collision` (значения различаются — видны локальное и
входящее), `missing_local` (нет у нас), `missing_incoming` (нет в пакете),
`ambiguous` (ключ повторяется внутри одной стороны — выбор за человеком).

Значения сравниваются по смыслу: `64` = `64.0`, отсутствующее поле = `null` =
пустая строка, пробелы по краям не различие. Регистр и написание — различие:
ключ находит запись, а расхождение в написании остаётся видимым. Поля
`org_name` и `*_id` не сравниваются.

## Протокол разногласий

`BuildProtocol` выгружает XLSX: лист «Сводка» (отправитель, подписант, хеш
пакета, счётчики, число различий без решения) и лист «Различия» — все различия
по одному полю на строку и решение оператора (принять, оставить, добавить) с
причиной, автором и временем. Различие без решения помечено «не принято».
Значения записываются текстом: формула из чужого пакета не выполняется.
