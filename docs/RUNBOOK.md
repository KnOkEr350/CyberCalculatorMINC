# Runbook эксплуатации (OPS-12)

Инстанс разворачивается в закрытом контуре, где внешнего мониторинга может не
быть. Поэтому состояние подсистем читается из самой системы, а этот документ
говорит, что делать с каждым показателем.

## Где смотреть

`GET /api/admin/metrics` — один срез по всем подсистемам, доступен
администратору. Возвращает JSON с разделами `timers`, `snapshot`, `storage`,
`audit`, `database`.

```
curl -s --cookie "cybercalc_session=<токен>" https://<хост>/api/admin/metrics | jq
```

Отдельно:

- `GET /api/live` — контейнер жив (без обращения к базе);
- `GET /api/ready` — готов принимать запросы (с проверкой базы);
- `GET /api/admin/logs/export` — потоковая выгрузка журнала с проверкой цепочки.

## Регламентные сроки (`timers`)

| Показатель | Норма | Что делать при отклонении |
|---|---|---|
| `next_deadline`, `days_left` | ближайшая контрольная дата Приказа № 270 | при `days_left <= 14` предупредить ответственных: сроки календарные, выходные их не переносят (ADR-02) |
| `overdue` | `0` | каждая просроченная дата — пропущенный регламентный срок; разобрать по экрану «Отчётность», зафиксировать причину |

Сроки считаются по московским датам на сервере. Если показатель расходится с
ожиданием, сверьте часовой пояс контейнера: смещение клиента на расчёт не
влияет, а смещение сервера — влияет.

## Снимок на 1 мая (`snapshot`)

| Показатель | Норма | Что делать при отклонении |
|---|---|---|
| `sealed` | `true` после 1 мая отчётного года | без снимка Приложение № 4 не формируется (409). Снимок создаётся **только 1 мая** по московскому времени и повторно за тот же год не создаётся |

Если 1 мая пропущено, снимок задним числом не создаётся: это осознанное
ограничение неизменяемости. Решение принимает владелец продукта.

## Хранилище (`storage`)

| Показатель | Норма | Что делать при отклонении |
|---|---|---|
| `documents` / `distinct_blobs` | `distinct_blobs <= documents` | равенство означает отсутствие дедупликации; сильный разрыв — норма (один документ приложен к нескольким мероприятиям) |
| `quarantined` | `0` | файлы приняты при недоступном антивирусе и не выдаются. Поднять антивирус, затем перезалить документы |
| `unscanned` | `0` | исторические файлы, загруженные до появления антивирусной проверки. Проверить вручную |
| `deletion_queue` | близко к `0` | очередь растёт — фоновая очистка не справляется или падает. Проверить журнал контейнера backend на `retention:` |
| `expiring_in_week` | — | документы, у которых на неделе истекает срок хранения. Если они ещё нужны, продлить `attachment_retention_days` **до** истечения |

Файл удаляется с диска только когда исчезает последняя ссылка на него:
содержимое адресуется хешем и может принадлежать нескольким вложениям.

## Журнал аудита (`audit`)

| Показатель | Норма | Что делать при отклонении |
|---|---|---|
| `chain_verified` | `true` | `false` означает нарушенную цепочку: запись изменена, удалена или пропущена. Выгрузка журнала при этом отказывает (409) |
| `chain_problem` | пусто | текст называет вид нарушения и номер звена |
| `records` / `archived` | растут | записи старше срока хранения уходят в архив, а не удаляются |

**Нарушенная цепочка — инцидент, а не сбой.** Журнал не изменяется ни
приложением (нет прав на `UPDATE`/`DELETE`), ни через триггер. Разрыв означает
вмешательство в базу или восстановление из неполной копии. Порядок действий:
зафиксировать номер звена, снять копию базы, не продолжать работу до разбора.

## База данных (`database`)

| Показатель | Норма | Что делать при отклонении |
|---|---|---|
| `reachable` | `true` | `false` — backend не видит базу; проверить контейнер postgres и параметры подключения |
| `latency_ms` | единицы миллисекунд | десятки и сотни — нагрузка или нехватка ресурсов |
| `active_sessions` | — | резкий рост при неизменном числе пользователей — повод проверить журнал входов |

## Частые задачи

**Сотрудник потерял устройство со вторым фактором.** Системный администратор:
`POST /api/admin/users/{id}/mfa-reset`. Второй фактор снимается вместе с кодами
восстановления, все сессии пользователя закрываются, событие попадает в журнал.

**Утрачен доступ системного администратора.** Оператор с доступом к хосту
задаёт `ADMIN_BOOTSTRAP_EMAIL` и `ADMIN_BOOTSTRAP_PASSWORD` и перезапускает
backend: учётная запись создаётся или включается заново с новым паролём, её
прежние сессии закрываются. В журнале контейнера появится строка
`восстановлен доступ системного администратора`.

**Перенос старых вложений в адресуемое хранилище.**
`storagemigrate <dsn> <каталог>`. Команда идемпотентна; код возврата `3`
означает, что остались строки для ручного разбора (файл потерян или его хеш не
совпал) — их перечисляет отчёт.

**Антивирус недоступен, загрузка нужна сейчас.** Осознанно переключить
`SCANNER_UNAVAILABLE_POLICY=quarantine`: файлы будут приниматься, но не будут
выдаваться до проверки. Вернуть `reject` после восстановления антивируса.
