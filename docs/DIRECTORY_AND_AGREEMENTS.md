# Справочник образовательных организаций и соглашения

## Почему старые 1 257 записей нельзя выбирать

Начальный набор получен из мониторинга ВО 2025. Он сохранён как исторический
источник, но не содержит ИНН, ОГРН и текущий статус лицензии. Поэтому приложение
не выдаёт его за полный реестр и не разрешает создавать из него новых партнёров.
Существующие партнёры и их расчёты не удаляются.

## Направления вузов по приказу

Пункт 1 приказа № 270 в `tz/Приказ_270_2026_fin.docx` отсылает к приказу
Минцифры № 27 от 22.01.2026, приложение № 3
([официальная публикация Минюста](https://minjust.consultant.ru/documents/58398)).
Список вузов и создание нового партнёра требуют хотя бы одного **точного**
совпадения кода программы с этим перечнем. Например, `38.03.05` подходит,
а `38.03.01` и укрупнённая группа `09.00.00` — нет.

Коды и ссылку на источник можно сохранить в карточке либо в дополнительных
столбцах Excel «Коды направлений» и «Источник направлений».
Старые файлы с 11 столбцами по-прежнему принимаются и не очищают уже известные
направления. В режиме проверки можно включить «Показать также вузы без
подтверждённого направления». Эти записи нельзя выбрать для нового соглашения.
Школы, СПО и существующие партнёры сохраняются.

Для сбора кодов с официальных сайтов учебных заведений:

```bash
bash scripts/enrich-directory-programs.sh
# При необходимости ограничить один запуск:
DIRECTORY_ENRICH_LIMIT=100 bash scripts/enrich-directory-programs.sh
```

Сборщик берёт сайт конкретной записи/филиала из мониторинга и читает таблицы
`/sveden/education/`. Он не выводит специальности из названия вуза или группы
мониторинга. Четыре запроса обрабатываются параллельно; повторный запуск
продолжает с записей, которые проверялись раньше остальных, пропуская успешно
проверенные за последние 35 дней. Необычный адрес страницы, отсутствие кодов,
ошибка сети или запрет доступа требуют ручной проверки; известные данные при
ошибке сохраняются. Сборщик не подтверждает лицензию и защищает изменения,
сохранённые проверяющим после начала запуска.

## Массовая загрузка ИТ-компаний

Прежние три записи были начальным набором, зашитым в сервер, а не результатом
поиска по полному реестру. Автоматическое создание этого набора удалено;
существующие записи сохранены. Для наполнения используется актуальная выгрузка
аккредитаций, а не список правообладателей ПО или исторический архив.

Во вкладке «ИТ-компании» нажмите «Загрузить выгрузку», скачайте шаблон,
проверьте файл и выполните загрузку. Поддерживаются CSV UTF-8 (запятая или
точка с запятой, до 100 000 строк) и XLSX (до 10 000 строк; общий защитный
лимит Excel-парсера), до 32 МБ. Заголовки могут быть русскими из шаблона или:

```text
name,inn,ogrn,accreditation_number,accreditation_status,registry_record_id,registry_updated_at,source_url,notes
```

Обязательны `name`, `inn`, `ogrn`, `registry_updated_at` (ГГГГ-ММ-ДД),
`source_url` (официальный HTTPS-источник). Без `registry_record_id` используется
ИНН. Пустой статус означает `active`; также допустимы `suspended` и `revoked`.
Сведения о действующей аккредитации должны быть не старше 35 дней.
Импорт обновляет записи по ИНН, обрабатывает исключения из реестра,
не создаёт дубли и полностью откатывается при конфликте реквизитов,
попытке заменить более новые сведения или ошибке строки.
Отсутствие компании в частичной выгрузке не означает отзыв аккредитации.

Тот же импорт из командной строки:

```bash
bash scripts/sync-it-companies.sh /path/to/registry.csv
bash scripts/sync-it-companies.sh https://official-source.gov.ru/registry.xlsx
```

Скрипт использует контейнер backend с ограниченными правами БД. Пустой ответ,
HTML-страница или ошибка источника приводят к ошибке, а не к успешной загрузке
нескольких записей. Поиск выполняется по всей загруженной базе; интерфейс
показывает страницы по 500 записей без прежнего общего ограничения 10 000.
Публичная проверка отдельной аккредитации: <https://www.gosuslugi.ru/itorgs>.
Постоянный доступный URL полной актуальной выгрузки в проект не предоставлен.

## Первичная загрузка официального справочника

Администратор открывает «Учебные заведения» → «Обновить из выгрузки реестра»,
скачивает шаблон и переносит в него официальную выгрузку. Для каждой строки
обязательны:

- полное наименование, тип и субъект РФ;
- ИНН и ОГРН/ОГРНИП (сервер проверяет контрольные суммы);
- номер и текущий статус лицензии, статус юридического лица;
- устойчивый идентификатор записи, дата актуальности и HTTPS-ссылка на карточку
  Рособрнадзора либо другого официального домена `*.gov.ru`.

Импорт сначала выполняется в режиме проверки. Если ошибочна хотя бы одна строка,
в базу не записывается ничего. Проверенными и доступными для выбора считаются
только действующие записи, обновлённые не более 35 дней назад.

## Автоматическое обновление

Если официальный XLSX в формате шаблона доступен по постоянному HTTPS-адресу,
задайте в `.env`:

```dotenv
DIRECTORY_SYNC_URL=https://официальный-домен.gov.ru/path/registry.xlsx
DIRECTORY_SYNC_INTERVAL_HOURS=24
```

Backend проверяет выгрузку сразу после запуска и затем по расписанию. При двух
репликах обновление выполняет только одна из них. Ошибка не приводит к частичной
замене справочника; результат последнего запуска виден на странице справочника.

## Соглашения

Новый партнёр создаётся только из проверенной записи и одновременно с первым
соглашением. После этого кнопка «Соглашения» позволяет завести дополнительные
соглашения, соглашение с РОИВ, общий договор для нескольких учебных заведений,
ответственных лиц обеих сторон и реквизиты подписания.

Каждая новая или изменённая запись плана/факта и каждая строка Excel-импорта
обязательно ссылаются на действующее соглашение, которое охватывает выбранное
учебное заведение и отчётный год. Старые соглашения мигрируются со статусом
«Требует проверки»: их нужно открыть, уточнить реквизиты и сохранить с реальным
статусом до внесения новых расчётов.

## РОИВ и школьные мероприятия

Региональный орган управления образованием ведётся отдельной сущностью в
справочнике РОИВ. Для него обязательны полное наименование, субъект РФ, ИНН,
ОГРН, статус и ссылка на официальный HTTPS-источник.

Соглашение типа «С РОИВ» обязательно ссылается на действующий РОИВ и может
охватывать только школы. Обычное соглашение с образовательной организацией не
может использоваться для новой школьной активности. Таким образом, связь
проверяется сервером по цепочке:

`РОИВ → соглашение → одна или несколько школ → записи плана/факта`.

Если РОИВ переведён в статус «Не действует», существующая история сохраняется,
но новые школьные записи по его соглашениям блокируются. Название РОИВ также
выводится в Excel- и Word-отчётах.
