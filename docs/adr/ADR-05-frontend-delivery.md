# ADR-05: Способ доставки frontend

- Статус: `ACCEPTED`
- Дата решения: 23 сентября 2026 года
- Владелец решения: технический руководитель
- Backlog: Technical
- Блокирует: OPS-01, OPS-04, OPS-11

## Контекст

Сейчас frontend поставляется отдельным nginx-контейнером. ТЗ 4.4 допускает
единый appliance, для которого возможна раздача SPA из Go через `go:embed`.

## Варианты

1. Сохранить отдельный frontend-контейнер.
2. Встроить собранный frontend в Go-бинарник.
3. Поддерживать оба режима из одного воспроизводимого артефакта.

## Решение

Frontend встраивается в серверный Go-бинарник через `go:embed`. Сборка
контейнера сначала формирует детерминированный каталог SPA и копирует его в
пакет `internal/modules/webapp` до компиляции. Отдельный frontend-контейнер в
runtime не используется. Nginx остаётся внешним reverse proxy для TLS, WAF,
rate limiting и ограничения multipart-запросов.

`index.html` и `version.txt` отдаются с `Cache-Control: no-store`, остальные
нехешированные ресурсы — с обязательной ревалидацией. Неизвестные клиентские
маршруты получают SPA shell, но неизвестные `/api/*` и отсутствующие файлы
остаются `404`.

Offline bundle содержит один образ приложения вместо согласованной пары
backend/frontend. Upgrade заменяет образ приложения после preflight и backup;
rollback возвращает предыдущий образ и бинарник вместе с соответствующей SPA.

## Критерий принятия

Выбрана целевая схема, описаны cache headers, CSP, offline bundle, обновление и
rollback; smoke test проходит без доступа к сети.

Критерий закрыт unit-тестом embedded handler и container build, не требующим
сетевой загрузки frontend во время исполнения.
