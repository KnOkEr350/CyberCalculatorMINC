# ADR-15: Ручные и вычисляемые признаки риска

- Статус: `ACCEPTED`
- Владелец решения: владелец продукта совместно с юристом
- Дата решения: 21 сентября 2026 года
- Основание: решение встречи
- Блокирует: —

## Контекст

Часть рисков может следовать из объективных данных, а часть подтверждается
пользователем или юристом. Нужно исключить ситуацию, когда ручной чекбокс
перекрывает отсутствующий документ или отрицательную автоматическую проверку.

## Решение

Риск существует только внутри системы и всегда вычисляется из версионированных
правил над предметными данными, документами, сроками, eligibility, approval и
активным юридическим сомнением.

- Пользователь не может вручную выбрать зелёный/жёлтый/красный статус.
- Risk status не экспортируется как нормативный реквизит приказа.
- Подтверждения и документы меняют исходные факты, после чего движок
  пересчитывает риск.
- Юрист может создать отдельное `legal_dispute`, но не подменить результат
  risk rule произвольным чекбоксом.
- Каждый результат содержит ruleset version, причины и ссылки на факты.

## Последствия

Из моделей API и таблиц удаляются пользовательские поля вида `risk_checked` и
`manual_risk`. В официальную зачётную сумму входят только данные по ADR-18/19;
цвет риска сам по себе сумму не меняет.
