# ADR-18: Соотношение readiness, eligibility и approval

- Статус: `ACCEPTED`
- Владелец решения: владелец продукта совместно с юристом
- Дата решения: 21 сентября 2026 года
- Основание: Приказ № 270, решение встречи
- Блокирует: —

## Контекст

Комплектность данных, регуляторная допустимость и формальное согласование —
разные состояния. Их смешение приводит к включению незачётных сумм в отчёт
или блокирует работу с ещё не согласованными черновиками.

## Решение

- `readiness`: `draft/incomplete/ready`; отвечает только на вопрос, достаточно
  ли данных и документов для проверки.
- `eligibility`: `unknown/eligible/ineligible`; вычисляется по Приказу,
  Методике и действующим внешним правилам.
- `approval`: `not_required/pending/approved/default_approved/disputed/rejected`;
  описывает согласование перечня/документа. Приказ допускает явное подписание
  либо согласование по молчанию после календарного срока.
- `legal_dispute`: самостоятельное активное/снятое состояние с причиной; при
  активности projection получает `approval=disputed`.
- `risk`: производное внутреннее значение, а не четвёртый источник истины.

Черновик может сохраняться при любых состояниях. В предварительный или итоговый
перечень запись включается, когда `readiness=ready`, `eligibility=eligible`, нет
активного юридического сомнения, а требуемый workflow достиг допустимого для
конкретного этапа состояния.

`counted_amount` сначала вычисляется по ADR-19. Агрегат «подтверждённый факт»
учитывает его только после требуемого approval; отдельный прогноз может
показывать eligible pending записи, но не смешивает их с подтверждённым фактом.

## Последствия

API всегда возвращает все состояния и explanation отдельно. Цветовой индикатор
не используется как сокращение, способное скрыть нормативную причину.
