# ADR-02: Календарная политика таймеров

- Статус: `ACCEPTED`
- Владелец решения: владелец продукта совместно с юристом
- Дата решения: 21 сентября 2026 года
- Основание: Приказ № 270
- Блокирует: —

## Контекст

Приказ задаёт календарные, а не рабочие дни: `14/10/10` для проекта
соглашения, `10/10/5` для предварительного перечня и `20/20/10` для итогового.

## Решение

Срок хранится и вычисляется как дата:

- день получения не включается;
- первый день срока — следующий календарный день;
- выходные и праздники не исключаются и не переносят срок;
- позиция считается отсутствующей, а перечень — согласованным по умолчанию,
  после окончания последнего календарного дня срока;
- business timezone инстанса обязателен, по умолчанию `Europe/Moscow`; UTC
  хранится для аудита фактических событий.

Производственный календарь из пакета WF-02 удаляется. Нужен date-based
`CalendarDeadline`, тесты граничных дат и идемпотентный переход в
`default-approved`.

Если официальное толкование потребует перенос окончания срока, решение
заменяется новым ADR; текущая копия приказа такого правила не содержит.
