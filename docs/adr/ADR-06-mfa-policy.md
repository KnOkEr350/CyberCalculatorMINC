# ADR-06: Политика обязательности 2FA

- Статус: `ACCEPTED`
- Владелец решения: Security owner
- Дата решения: 21 сентября 2026 года
- Основание: решение встречи
- Блокирует: —

## Контекст

ТЗ описывает вход с TOTP, а текущая система позволяет пользователю работать
без включённой 2FA. Нужно определить обязательность по ролям и переходный
период для существующих аккаунтов.

## Решение

`SUPER_ADMIN` включает и выключает глобальную политику обязательного TOTP для
инстанса. Другие роли менять её не могут.

- При включении задаётся grace period для уже существующих пользователей;
  новые пользователи проходят enrollment при первом входе.
- После grace period вход без завершённого TOTP запрещён для всех интерактивных
  пользователей, кроме документированного recovery/break-glass сценария.
- Выключение enforcement не удаляет существующие TOTP-секреты и recovery codes;
  пользователь может продолжать применять 2FA добровольно.
- Включение, выключение, reset, recovery и использование break-glass всегда
  записываются в неизменяемый аудит.
- API не позволяет администратору прочитать TOTP-секрет пользователя.

Начальное значение при первой установке задаётся first-boot wizard и явно
подтверждается главным администратором; скрытого значения по умолчанию нет.

Конкретная продолжительность grace period и процедура break-glass входят в
эксплуатационную конфигурацию и security runbook.
