## Как пользоваться

1. Администратор назначает профиль в «Админка → Пользователи → Профиль и доступ».
2. Сотрудник открывает «Учебные заведения», выбирает тип ОО, ищет организацию в справочнике и добавляет её в партнёры с реквизитами соглашения. Есть ручное добавление.
3. В справочнике партнёра добавляются наставники. Фамилия и имя обязательны, отчество — при наличии. При стажировке/практике выбирается наставник этого партнёра; сервер сохраняет его ФИО, а не произвольную подмену из запроса.
4. «План / Факт»: тип ОО → партнёр → год и период → доступная категория → запись. Для вузов показываются преподавание и ООП/РПД, с переходом к недостающей категории. Записи допускается сохранять постепенно, без файлов.
5. Можно выбрать до 20 вложений за раз, суммарно до 64 МБ, как для плана, так и для факта. Если запись сохранена, а загрузка не прошла, форма предлагает повторить загрузку, не создавая вторую запись. Ошибка одного файла отменяет весь пакет файлов.
6. «Импорт из Excel»: скачать шаблон, заполнить первый лист, проверить, затем импортировать. Контекст партнёра/категории/года/плана или факта берётся из выбранного раздела. Суммы рассчитываются сервером. В шаблоне наставник указывается полным именем из справочника партнёра.
7. Импорт: только `.xlsx`, до 8 МБ, 1000 строк мероприятий или 10000 организаций. Формулы заменяются значениями. Неизвестные/повторные столбцы, неверные числа, отрицательные значения и неизвестные наставники вызывают ошибки с номерами строк. Любая ошибка отменяет сохранение всех строк. Повтор того же файла тем же пользователем в том же контексте не создаёт дублей. Изменённый файл считается новым импортом; семантические дубли между разными файлами автоматически не определяются.
8. Экспорт Excel: сводный лист, отдельные листы партнёров, детализация по полям при выборе категории. Заголовок закреплён, включён автофильтр, длинные и совпадающие русские имена листов корректно обрабатываются. В справочнике наставников доступны ссылки на отчёты по наставнику за выбранный год. Word — редактируемая рабочая таблица, не утверждённая форма.

## Роли и доступ

| Профиль | Область доступа |
| --- | --- |
| `admin` | Все партнёры; пользователи, назначения профилей, настройки, импорт общего справочника, аудит |
| `user` + `organization` | Сотрудник Киберпротекта: все партнёры и их мероприятия; добавление партнёров и наставников |
| `user` + `edu_institution` + `partner_id` | Представитель ОО: только назначенный партнёр, его мероприятия, наставники, файлы и отчёты |
| Не назначенный профиль | Нет доступа к данным партнёров; необходимо назначение администратором |

`organization` обозначает внутреннего сотрудника Киберпротекта, а не стороннюю компанию-партнёра. Представитель не может сам переключить профиль на сотрудника. Доступ проверяется сервером также для комментариев, прямых ссылок скачивания, дашборда, экспорта и импорта. Последнего активного администратора отключить/понизить нельзя.

Целевая сумма дашборда сохраняет модель из удалённого коммита: она персональна для учётной записи и года (`budget_targets.owner_user_id`), а суммы мероприятий охватывают доступных пользователю партнёров. Сумма в интерфейсе подписана «Моя целевая сумма»; изменение цели одного сотрудника не меняет цель другого. При фильтрации по партнёру общая личная цель не показывается. Выпущенная миграция `0004_data_ownership.sql` сохранена; новые миграции имеют отдельные имена.

Перед выпуском администратору необходимо проверить старые назначения: в прежней версии пользователи могли выбирать `entity_type` самостоятельно. Миграция намеренно не угадывает, кто из существующих пользователей является сотрудником. Без проверки старых профилей корректность их исторического назначения гарантировать нельзя.

## Справочник организаций

`0005_education_directory_seed.sql` содержит 1257 уникальных записей вузов и филиалов из региональных списков [официального мониторинга ВО 2025](https://monitoring.miccedu.ru/?m=vpo&year=2025), проверенных 09.09.2026. У каждой записи указан URL карточки источника. Прочитаны все 89 региональных страниц, перечисленных источником, без пропущенных запросов.

Это перечень участников мониторинга, НЕ полный актуальный реестр лицензий всех вузов России. Закрытые, не участвовавшие, новые или реорганизованные организации могут отсутствовать либо требовать сверки. Наличие в справочнике не подтверждает правовую допустимость соглашения по приказу. Школы и СПО в этот исходный набор не входят. Для них предусмотрены типизированный ручной ввод партнёров и импорт справочника администратором. Публичное HTTP-приложение не обращается к внешнему источнику при работе пользователя.

`scripts/read_monitoring_directory.py` позволяет повторно прочитать официальный источник в JSON на stdout, но сам не изменяет БД и не обновляет миграцию автоматически. Справочник и реальные партнёры разделены: загрузка 1257 организаций не создаёт 1257 соглашений. Повторное добавление одного `directory_id` как партнёра блокируется; совпадения вручную введённых названий не склеиваются автоматически.

## Обязательности и приказ

Для вуза в выбранных году и плане/факте проверяются наличие преподавания и хотя бы одной записи ООП/РПД с положительной суммой. ТОП ИТ/ТОП ИИ с положительным софинансированием снимает эти две обязательности у данного партнёра. При выборе ТОП форма сразу сообщает об исключении; постоянный статус меняется только после сохранения. Факт не наследует исключение из плана, следующий год — из предыдущего. ТОП для новых записей доступен только вузам. Старые записи СПО остаются читаемыми, но не соответствующие новой области применения записи ТОП нельзя повторно сохранить без уточнения модели.

В предоставленном приказе исключение ТОП дополнительно связано с реализацией иных видов мероприятий хотя бы в одной другой образовательной организации. Это условие **не проверяется автоматически**: интерфейс явно предупреждает о ручной проверке. Для СПО и школ двойная обязательность высшего образования автоматически не навязывается. Суммы дашборда — суммы внесённых мероприятий, а не юридически подтверждённые допустимые затраты.

Презентация с образцами Word/Excel не найдена в предоставленных местах. Точное оформление по презентации не проверено. Word и Excel здесь являются рабочими выгрузками и не заменяют согласованные формы приложений 4/5 приказа. Автоматически не проверяются все правовые условия: статус ОО и соглашений, ИТ-специальности, опыт преподавателей, отсутствие бюджетного финансирования, включение РПД в ООП без двойного счёта, цифровой след и аудиторское подтверждение фактических затрат.

## Хранение и совместимость

- Данные пользователей, партнёров, наставников, справочника и плана/факта находятся в PostgreSQL. Автоматического удаления этих записей нет.
- Файлы находятся в томе uploads; в БД — метаданные и дата истечения срока. Срок новых файлов берётся из настройки `attachment_retention_days` (по умолчанию 365 дней). Фоновая очистка работает при запуске и затем ежечасно. Просроченный файл перестаёт скачиваться сразу по дате, даже до фонового удаления. Изменение настройки не пересчитывает срок ранее загруженных файлов.
- Временные файлы разбора multipart удаляются после запроса; Excel импорта не сохраняется как вложение. Для защиты от повторного импорта сохраняется SHA-256 отпечаток файла и контекста с пользователем/датой, без самого файла; автоматического удаления отпечатков нет.
- Миграция 0004 создаёт справочники/индексы и переносит имеющиеся ФИО наставников в справочник, добавляя идентификатор в JSON записей. Сами записи и вложения не удаляются. 0005 заполняет общий справочник. Миграции применяются стандартным механизмом проекта под блокировкой.
- Числовые ставки и формулы калькуляторов не менялись. Для стажировок добавлена обязательная связь с наставником. Старые клиенты могут передать существующее в справочнике ФИО без идентификатора; произвольное новое имя автоматически не добавляется.
- Не смешивать старые и новые версии фронтенда/бэкенда при выпуске. Перед выпуском: резервная копия БД и uploads, проверка миграций на копии, аудит профилей, согласованный выпуск обеих частей. Обратная миграция с удалением новых таблиц не предусмотрена; не удалять данные для отката.

## Локальная проверка

Тестовый адрес: http://localhost:18081. Только тестовый вход: `admin@workspace.test` / `WorkspaceTest1!`. Эти данные не следует использовать на внешнем сервере.

```sh
HTTP_PORT=18081 BACKEND_REPLICAS=1 DB_USER=workspace_test DB_PASSWORD=workspace_test DB_NAME=workspace_test ADMIN_BOOTSTRAP_EMAIL=admin@workspace.test ADMIN_BOOTSTRAP_PASSWORD='WorkspaceTest1!' docker compose -p cybercalc-workspace-test up -d --build
```

`backend/cmd/server/workspace_integration_test.go` запускается только с `TEST_DATABASE_DSN`, содержащим `dbname=workspace_test`, и после применения миграций. Проверяет HTTP-сценарии, а не только функции: ACL, расчёты, наставников, ТОП по периодам/годам, пакетные файлы, срок хранения, атомарный импорт/дубли, справочник и экспорты. Также добавлены unit-тесты областей доступа, обязательностей, ФИО, ZIP/XML, формул Excel и имён листов. Использованы `go test -race ./...`, `go vet ./...`, `node --check` и браузерный `scripts/workspace_smoke.cjs`.

После объединения с удалённым коммитом тесты повторены. Дополнительно `backend/internal/dbx/migrations_integration_test.go` проверил на отдельной одноразовой БД переход со схемы 0001–0003 через обе миграции 0004 и наполнение 0005: старая запись, её сумма, метаданные файла и бюджет сохранились; ФИО перенеслось в справочник; загружено ровно 1257 организаций; повторный запуск миграций не изменил результат. Тест требует `TEST_MIGRATION_DATABASE_DSN` с `dbname=workspace_migration_test` и `TEST_MIGRATIONS_DIR`.

Браузерный тест использует Playwright; `PLAYWRIGHT_MODULE` позволяет указать уже установленный модуль, `PLAYWRIGHT_BROWSERS_PATH` — каталог браузеров. `TEST_BASE_URL` по умолчанию `http://127.0.0.1:18081`; внешние хосты запрещены. Тесты создают только синтетические данные в изолированном проекте. Остановка без удаления тестовых данных: `docker compose -p cybercalc-workspace-test stop`. Не использовать `down -v` для рабочего проекта.
