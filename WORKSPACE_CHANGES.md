## Как пользоваться

1. Администратор назначает профиль в «Админ. панель → Пользователи → Профиль и доступ».
2. Администратор или модератор открывает в «Админ. панели» раздел учебных заведений, выбирает тип ОО, ищет организацию в справочнике и добавляет её в партнёры с реквизитами соглашения.
3. У обычного профиля ИТ-организации вместо вкладки учебных заведений показывается «ИТ-компании»: действующие аккредитации можно искать и добавлять после проверки в официальном сервисе Госуслуг.
4. В справочнике партнёра добавляются наставники. Фамилия и имя обязательны, отчество — при наличии. При стажировке/практике выбирается наставник этого партнёра; сервер сохраняет его ФИО, а не произвольную подмену из запроса.
5. «План / Факт» заполняет обязанная ИТ-организация: тип ОО → партнёр → год и период → доступная категория → запись. Для вузов показываются преподавание и ООП/РПД, с переходом к недостающей категории. Записи допускается сохранять постепенно, без файлов. Представитель ОО видит только назначенное учебное заведение и не выбирает другую ОО: он просматривает направленные данные, а по факту согласует перечень либо возвращает его с замечаниями.
6. Можно выбрать до 20 вложений за раз, суммарно до 64 МБ, как для плана, так и для факта. Если запись сохранена, а загрузка не прошла, форма предлагает повторить загрузку, не создавая вторую запись. Ошибка одного файла отменяет весь пакет файлов.
7. «Импорт из Excel»: скачать шаблон с русскими заголовками, заполнить первый лист, проверить, затем импортировать. Контекст партнёра/категории/года/плана или факта берётся из выбранного раздела. Суммы рассчитываются сервером. В шаблоне наставник указывается полным именем из справочника партнёра.
8. Импорт: только `.xlsx`, до 8 МБ, 1000 строк мероприятий или 10000 организаций. Формулы заменяются значениями. Неизвестные/повторные столбцы, неверные числа, отрицательные значения и неизвестные наставники вызывают ошибки с номерами строк. Любая ошибка отменяет сохранение всех строк. Повтор того же файла тем же пользователем в том же контексте не создаёт дублей. Изменённый файл считается новым импортом; семантические дубли между разными файлами автоматически не определяются.
9. Экспорт Excel/Word открывается только после последовательных статусов «Готово» → «Проверено» → «Утверждено» для выбранного соглашения, года и плана/факта. Любое изменение соглашения, его перечня мероприятий или записи возвращает соответствующий отчёт в черновик.

## Роли и доступ

| Профиль | Область доступа |
| --- | --- |
| `admin` | Все партнёры; пользователи, назначения профилей, настройки, импорт общего справочника, аудит |
| `moderator` | Операционные функции; справочник ИТ-компаний доступен только профилю ОО; без пользователей, настроек и журнала изменений |
| `user` + `organization` | Представитель ИТ-организации: все рабочие партнёры и их мероприятия; отдельная вкладка аккредитованных ИТ-компаний |
| `user` + `edu_institution` + `partner_id` | Представитель ОО: только назначенный партнёр; просмотр его плана, отчёта и файлов; согласование направленного перечня факта или возврат с замечаниями; без создания и изменения данных ИТ-организации |
| Не назначенный профиль | Нет доступа к данным партнёров; необходимо назначение администратором |

`organization` обозначает профиль обязанной ИТ-организации, а `edu_institution` — профиль конкретного учебного заведения. Представитель не может сам переключить профиль. Доступ проверяется сервером также для комментариев, прямых ссылок скачивания, дашборда, экспорта и импорта. Последнего активного администратора отключить/понизить нельзя.

Целевая сумма дашборда сохраняет модель из удалённого коммита: она персональна для учётной записи и года (`budget_targets.owner_user_id`), а суммы мероприятий охватывают доступных пользователю партнёров. Сумма в интерфейсе подписана «Моя целевая сумма»; изменение цели одного сотрудника не меняет цель другого. При фильтрации по партнёру общая личная цель не показывается. Выпущенная миграция `0004_data_ownership.sql` сохранена; новые миграции имеют отдельные имена.

Перед выпуском администратору необходимо проверить старые назначения: в прежней версии пользователи могли выбирать `entity_type` самостоятельно. Миграция намеренно не угадывает, кто из существующих пользователей является сотрудником. Без проверки старых профилей корректность их исторического назначения гарантировать нельзя.

## Справочник организаций

`0005_education_directory_seed.sql` содержит 1257 уникальных записей вузов и филиалов из региональных списков [официального мониторинга ВО 2025](https://monitoring.miccedu.ru/?m=vpo&year=2025), проверенных 09.09.2026. У каждой записи указан URL карточки источника. Прочитаны все 89 региональных страниц, перечисленных источником, без пропущенных запросов.

Это перечень участников мониторинга, НЕ полный актуальный реестр лицензий всех вузов России. Закрытые, не участвовавшие, новые или реорганизованные организации могут отсутствовать либо требовать сверки. Наличие в справочнике не подтверждает правовую допустимость соглашения по приказу. Школы и СПО в этот исходный набор не входят. Для них предусмотрены типизированный ручной ввод партнёров и импорт справочника администратором. Поиск вузов читает локальную базу.

По умолчанию показаны вузы с точными кодами из перечня приказа. Коды загружаются с собственного сайта каждой организации, включая HTML внутри `__NEXT_DATA__`, размеченные элементы `eduCode` и ссылки на таблицы образовательных программ. При `DIRECTORY_ENRICH_ON_START=true` обновление запускается в фоне и повторяется через `DIRECTORY_SYNC_INTERVAL_HOURS`; неудачные запросы сохраняют ранее найденные направления. Ручной запуск: `bash scripts/enrich-directory-programs.sh`, выборочная проверка: `bash scripts/enrich-directory-programs.sh 'Баумана'`. Вузы без найденных кодов доступны через флажок проверки. API возвращает страницы по 500 записей, интерфейс дочитывает остальные; счётчики отдельно показывают весь справочник, подходящие направления и подтверждённые реквизиты.

ИТ-компании по умолчанию загружаются из локального списка сохранённых записей. Онлайн-проверка по названию или ИНН через публичный сервис [ПроРеестр](https://www.proreestr.ru/it-akkreditaciya/) запускается при выборе этого источника и непустом запросе. При 100 совпадениях нужно уточнить запрос. Это поиск, а не полная выгрузка реестра. Источник указан в интерфейсе; отсутствующие в ответе ОГРН и номера аккредитации не подставляются. «Сохранённые компании» показывает отдельный локальный список с импортом CSV/XLSX и ручным добавлением. При сбое внешнего сервиса можно повторить проверку или открыть сохранённые компании. Загрузка локального списка не зависит от внешнего сервиса.

`scripts/read_monitoring_directory.py` позволяет повторно прочитать официальный источник в JSON на stdout, но сам не изменяет БД и не обновляет миграцию автоматически. Справочник и реальные партнёры разделены: загрузка 1257 организаций не создаёт 1257 соглашений. Повторное добавление одного `directory_id` как партнёра блокируется; совпадения вручную введённых названий не склеиваются автоматически.

## Обязательности и приказ

В каждом соглашении хранится явный перечень применимых видов мероприятий. Готовность требует положительную серверно рассчитанную запись по каждому виду перечня. Для ВО нельзя исключить одновременно преподавание и ООП/РПД без включения ТОП ИТ/ИИ. Само наличие ТОП не даёт автоматического освобождения: исключение применяется только тогда, когда в другой образовательной организации утверждены преподавание, ООП/РПД, стажировка или практика с трудоустройством и мероприятие по решению Минцифры в том же году и срезе.

Положительной суммы недостаточно. Перед направлением ИТ-организация подтверждает соответствие конкретному перечню/объёму/срокам соглашения, выполнение условий приложения № 1 и наличие подтверждающих документов. Для факта после этого ОО или РОИВ отдельно рассматривает перечень: представитель контрагента согласует его либо возвращает с замечаниями; администратор или модератор может зафиксировать согласование по истечении предусмотренного приказом срока. Загрузка файлов остаётся необязательной. Утверждение выполняет администратор или модератор. На дашборде отдельно показаны все расчёты и только суммы записей из юридически комплектных утверждённых отчётов.

Презентация с образцами Word/Excel не найдена в предоставленных местах. Точное оформление по презентации не проверено. Выгрузка допускается только после внутреннего утверждения, но не является электронной подписью и сама по себе не заменяет форму приложений 4/5 приказа. Те юридические факты, которые нельзя достоверно вывести из полей калькулятора (опыт преподавателей, отсутствие бюджетного финансирования, включение РПД в ООП, цифровой след и достаточность первичных документов), фиксируются обязательным подтверждением ответственного лица и последующей проверкой/утверждением, а не объявляются автоматически выполненными.

## Хранение и совместимость

- Данные пользователей, партнёров, наставников, справочника и плана/факта находятся в PostgreSQL. Автоматического удаления этих записей нет.
- Файлы находятся в томе uploads; в БД — метаданные и дата истечения срока. Срок новых файлов берётся из настройки `attachment_retention_days` (по умолчанию 365 дней). Фоновая очистка работает при запуске и затем ежечасно. Просроченный файл перестаёт скачиваться сразу по дате, даже до фонового удаления. Изменение настройки не пересчитывает срок ранее загруженных файлов.
- Временные файлы разбора multipart удаляются после запроса; Excel импорта не сохраняется как вложение. Для защиты от повторного импорта сохраняется SHA-256 отпечаток файла и контекста с пользователем/датой, без самого файла; автоматического удаления отпечатков нет.
- Миграция 0004 создаёт справочники/индексы и переносит имеющиеся ФИО наставников в справочник, добавляя идентификатор в JSON записей. Сами записи и вложения не удаляются. 0005 заполняет общий справочник. Миграции применяются стандартным механизмом проекта под блокировкой.
- Числовые ставки и формулы калькуляторов не менялись. Для стажировок добавлена обязательная связь с наставником. Старые клиенты могут передать существующее в справочнике ФИО без идентификатора; произвольное новое имя автоматически не добавляется.
- Не смешивать старые и новые версии фронтенда/бэкенда при выпуске. Перед выпуском: резервная копия БД и uploads, проверка миграций на копии, аудит профилей, согласованный выпуск обеих частей. Обратная миграция с удалением новых таблиц не предусмотрена; не удалять данные для отката.

## Исправление доступа к ИТ-компаниям 15.09.2026

Образовательные профили всех ролей могут просматривать список и проверять аккредитацию. Обычный пользователь ОО не может добавлять или импортировать компании. Администраторы и модераторы работают со справочником противоположного типа: профиль `organization` видит ОО, профиль `edu_institution` — ИТ-компании. Скрытые справочники недоступны при прямом открытии; сервер также проверяет профиль. У администраторов и модераторов ОО скрыт переход «Справочник и соглашения» из плана/факта. Начальная загрузка читает сохранённый список, пустой онлайн-поиск не делает внешний запрос.

Проверка интерфейса с изолированными API-данными: `PLAYWRIGHT_MODULE=/path/to/playwright CHROME_EXECUTABLE=/path/to/chrome node scripts/it_company_ui_smoke.cjs`. Проверяются 650 записей, страницы 500/150, фильтр по ИНН, просмотр ОО, все четыре сочетания административной роли и типа организации, отсутствие запросов при прямом открытии скрытых справочников и возврат к сохранённому списку при сбое онлайн-проверки.

При объединении с обновлённым интерфейсом и миграцией `0018_user_entity_assignments.sql` ограничения справочников сохранены. Экран пользователей получает варианты назначения через административный API `/api/admin/it-company-options` (только ID, название и ИНН действующих компаний, с пагинацией). Это позволяет администратору ИТ назначать компанию пользователю без доступа к полному реестру аккредитаций. Браузерный тест дополнительно проверяет загрузку всех 650 вариантов и переключение типа назначения.
